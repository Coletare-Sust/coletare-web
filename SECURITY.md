# Política de segurança

## Como reportar

Não abra issue pública. Use o relato privado do GitHub (aba **Security** > **Report a vulnerability**) ou escreva para o responsável pelo projeto. Informe o componente, os passos para reproduzir e o impacto. Não inclua dados reais de usuários.

## Prazos de resposta

| Severidade | Primeira resposta | Correção alvo |
| --- | --- | --- |
| Crítica | 2 dias úteis | 7 dias |
| Alta | 3 dias úteis | 30 dias |
| Média ou baixa | 7 dias úteis | próxima release |

## Segredos expostos

Se uma chave, senha ou token foi commitado, trate como comprometido: **rotacione primeiro**, depois remova do código e do histórico. Remover o arquivo não invalida o segredo.

## Versões suportadas

Apenas a última release publicada recebe correções de segurança.
